# 사용자 검증 절차 (4명)

시드 `exit_conditions`의 "사용자 검증 합격선 도달"을 재는 방법이다.
합격선은 시드에 확정되어 있으므로 문항을 임의로 바꾸지 않는다.

```
링크: https://june-jiyun.github.io/financial-literacy-game/
1인당 20분 (플레이 15분 + 질문 5분), 4명을 각각 따로 만난다
```

## 합격선 (시드 원문)

| # | 기준 | 합격선 | 재는 방법 |
|---|------|--------|-----------|
| 1 | 무설명 첫 턴 완주 | 3/4 | **관찰** |
| 2 | 지표 2개 이상 자기 말로 설명 | 3/4 | 서술 질문 |
| 3 | 최대 영향 원인 선택 | 2/4 | **게임 결산 화면** |
| 4 | "부담 적다" 평가 | 3/4 | 5점 척도 |
| 5 | 재플레이 | 2/4 | **관찰** |

1·3·5번은 물어봐서 알 수 없다. 링크만 보내고 "어땠어요?"라고 물으면 이 세 개는
측정이 불가능하다. 그래서 **옆에서 보거나 화면공유로 지켜보는 방식**이 필요하다.

## 진행 규칙

**절대 설명하지 않는다.** 1번 기준이 "무설명"이므로, 게임 방법을 한마디라도
설명하면 그 사람의 1번 측정값은 버려야 한다. 질문을 받으면 이렇게만 답한다.

> "설명 없이 얼마나 알 수 있는지를 보는 중이라서요. 틀려도 괜찮으니 마음대로 눌러보세요."

**4명을 같이 만나지 않는다.** 먼저 한 사람이 알아낸 걸 옆에서 듣게 되면 나머지
3명의 1번 측정값이 오염된다.

**말은 사후에 시킨다.** 플레이 중에 "지금 뭐라고 생각했어요?"라고 물으면
플레이 자체를 방해한다. 질문은 결산 화면 이후로 모은다.

## 순서

### 1. 시작 (30초)

링크를 열어주고 이 문장만 말한다.

> "이거 한번 해보시고, 다 끝나면 몇 가지만 물어볼게요. 제가 설명은 안 할 거예요."

그리고 **입을 닫는다.** 타이머를 켠다.

### 2. 첫 턴 관찰 → 기준 ①

첫 턴에서 **원인 카드를 선택하고 결과 공개 화면까지 도달**하면 완주로 본다.

- 도움 없이 도달 → **합격**
- 막혀서 도움을 요청했고, 안내 없이는 진행 못 함 → **불합격** (안내해주고 계속 진행)

무엇에서 막혔는지 그 자리에서 적는다. 이게 다음 사이클에 쓸 가장 값진 정보다.

### 3. 끝까지 플레이 → 기준 ③

결산 화면에 턴별 `✓ 정답 / ✗ 오답`과 `n턴 중 m턴 정답`이 나온다.
이 게임의 정답 원인은 기여도 절댓값이 가장 큰 원인이므로, **결산 화면이 곧
기준 ③의 측정값이다.** 따로 물어볼 필요가 없다.

- `m ≥ 1` (한 턴이라도 정답) → **합격**

화면을 사진으로 찍어둔다. 서버 저장이 없으므로 창을 닫으면 사라진다.

### 4. 결산 화면에서 15초 침묵 → 기준 ⑤

아무 말도 하지 않는다. 스스로 다시 시작하면 **합격**이다.

15초 안에 아무 동작이 없으면 넘어간다. 이때 "또 하고 싶어요?"라고 물어서 받은
"네"는 **행동이 아니라 의향**이므로, 합격으로 세지 말고 기록지에 `의향만`으로
적는다.

### 5. 질문 (5분)

**기준 ② — 지표 설명.** 반드시 이 순서로, 객관식 없이 묻는다.

> "화면에 지표들이 있었죠. 그중에 기억나는 걸 아무거나, 그게 뭘 뜻하는 것 같았는지 말씀해주세요."

- 지표 **2개 이상**에 대해 자기 말로 뜻을 말하면 **합격**
- 이름만 읽는 것(예: "금리요")은 불합격. 뜻을 말해야 한다(예: "금리가 오르면 대출이 부담돼서 회사가 힘들어진다는 것 같았어요")
- 정답인지는 상관없다. **자기 말로 설명하는가**가 기준이다
- 보기를 주면 안 된다. 보기가 곧 답이 되어버린다

들은 말을 **그대로** 적는다. 요약하면 다음 사이클에서 못 쓴다.

**기준 ④ — 부담.**

> "이거 하는 게 얼마나 부담스러웠어요? 1이 전혀 부담 없음, 5가 매우 부담스러움이면 몇 점이요?"

- **1 또는 2** → 합격

**마무리 (선택, 합격선과 무관하지만 다음 사이클에 쓸 것)**

> "가장 헷갈렸던 데가 어디였어요?"
> "이거 뭐 하는 게임인 것 같았어요?"

## 기록지

1인당 이 표를 하나씩 채운다. 4장 인쇄해서 써도 된다.

```
검증자 __번   날짜 ______   경험 수준: 처음 / 조금 / 있음
소요 시간: ____분

① 무설명 첫 턴 완주        합격 / 불합격
   막힌 지점:

② 지표 2개 이상 설명       합격 / 불합격
   들은 말 그대로:


③ 최대 영향 원인 선택      n턴 중 __턴 정답  →  합격 / 불합격
   (결산 화면 사진 촬영: 예 / 아니오)

④ 부담 점수 (1~5)          __점  →  합격 / 불합격

⑤ 재플레이                 스스로 다시 시작 / 의향만 / 없음
                           →  합격 / 불합격

가장 헷갈린 곳:

무슨 게임이라고 생각했는지:
```

## 집계

4장을 모아 항목별로 합격 수를 센다.

```
① __/4  (필요 3)      ② __/4  (필요 3)      ③ __/4  (필요 2)
④ __/4  (필요 3)      ⑤ __/4  (필요 2)
```

**다섯 항목 모두 합격선을 넘어야** 시드의 "사용자 검증 합격선 도달"이 충족된다.
하나라도 미달이면 그 항목이 다음 사이클의 과제다.

## 알려진 제약

- **PC·노트북에서 진행할 것.** `@media` 반응형 규칙이 없어 좁은 화면 레이아웃은
  검증되지 않았다. 휴대폰으로 보내면 레이아웃 문제가 게임 이해도 문제로
  잘못 기록될 수 있다.
- **자동 수집이 없다.** 백엔드가 없는 설계이므로 플레이 기록은 어디에도 저장되지
  않는다. 위 기록지가 유일한 데이터다.
